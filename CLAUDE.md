## Verifying visuals (the browser pane is hidden here)
Hidden tabs don't run requestAnimationFrame/ResizeObserver, so normal screenshots of the canvas are black.
1. Always set a viewport first (`resize_window` 1280x800 or preset `mobile`) — the hidden default is 0×0 and the scene never starts.
2. Load `/?capture&quality=high` (or `low`; `static`; add `&boot` to show the loading screen; clear `sessionStorage['dc-boot-seen']` to see the full sequence).
3. In the page: `window.__rack.setStop(id)`, `.setTraffic(bool)`, `.orbit(deg)`, `.lookAt(px,py,pz,tx,ty,tz)`, `.render(frames)`, `.snapshot()`.
4. Save stills: run `node tools/capture-receiver.mjs` in the background (port 3999 → `.shots/`), then `fetch('http://127.0.0.1:3999/save?name=x.webp',{method:'POST',body:__rack.snapshot()})` and Read the file.
DOM overlays (cards, terminal, hero) do show in normal screenshots. Perf: `performance.getEntriesByType('measure')` entries named `dc:*`. Measure perf on a production build (`npx next build` + `npx next start -p 3001`), not dev.
Stop IDs: `overview`, `<deviceId>@<u>` (e.g. `fortigate-601f@34`, `proliant-dl360@20`), `kvm`, `wireless`, `monitoring`, `contact`, `terminal`.
Composite review trick: draw the canvas snapshot plus DOM rects (cards, hotspots, nav) onto one canvas and POST it to the receiver; CSS transitions don't run in the hidden pane, so read card state from `aria-hidden`, not computed opacity.

## Gotchas learned
- npm `overrides` for a package that is also a direct dependency must use `"$pkg"`, else `npm ci` fails (EOVERRIDE) — only fresh installs (Vercel) catch it.
- PowerShell: `Set-Content -Encoding utf8` writes a BOM; `git`/`npm` stderr shows as red errors even on success (check exit codes); here-strings with quotes break native args → use `git commit -F file`.
- camera-controls sets `touch-action:none`; the `.rack-canvas` CSS rule (`app/globals.css`) forces `pan-y` so phones can scroll past the hero. Wheel, trackpad and pinch zoom toward the cursor / pinch point (`dollyToCursor`; the wheel handler calls camera-controls' `_dollyInternal`). Closest zoom: `MIN_DISTANCE` 0.32 m (overview 0.55, it orbits a point behind the rack face); the turning arc narrows to half when close so the camera cannot swing into the rack. The wheel zooms the rack only while the page is at the top (scrollY ≤ 40); fully zoomed out (the overview framing is the max), scrolling down hands over to the page (custom `wheel` handler in `CameraRig`; camera-controls wheel stays NONE).
- Phones: the info card is a bottom sheet (~58% height), so stops lift the subject with a focal offset (+0.24·visH) and tall subjects use `fitH`; check every new stop on a 375×812 and a 360 px viewport.
- Phones (`pointer: coarse`): a one-finger SIDEWAYS swipe turns around the rack (polarRotateSpeed 0 on touch, azimuthRotateSpeed 0.45), up/down swipes scroll the page (canvas touch-action pan-y), two fingers pinch-zoom AND drag to slide the view (`TOUCH_DOLLY_TRUCK`, e.g. down to the servers/UPS). He loves this setup — keep it.
- Every stop fences its orbit point with `setBoundary` (overview: x ±0.6, y 0.35–2.15; other stops ±0.3 around their target). On the PHONE overview the fence is recomputed from zoom each frame: the picture's bottom edge may reach ~0.35 m (just enough to lift the console drawer + UPS above the view bar, which hides the rest), the top edge the rack top (~2 m), and the overview's own 1.35 m always stays allowed (he said the slide went "above and downward a lot": no fibres above the rack, no floor). Phone overview distance = fit half-width 0.40 (~1.7 m). so slides and cursor zooms never drift into empty space; capture `lookAt` clears the fence. Wheel zoom-out eases the orbit point back to the stop's centre (30%/notch), so scrolling fully out ends on the normal framing. The corner "Mohammad Yassin ▾" tab always resets to the overview framing.
- 3D hotspots are wrapped in `Spot`: each hides itself while its projected position is under the bottom UI (phones: bottom 130 px = view bar + toggles; desktop: bottom 72 px), so none sits on a bar button.
- Review helpers (paste into the page, see this session's approach): composite each stop (canvas snapshot + DOM cards/hotspots/nav drawn on top), tile them into contact sheets per viewport, and check hotspot-vs-button overlaps automatically.
- Phone hint ("Swipe to turn · two fingers zoom & move") sits left of the Live traffic / Sound toggles, width `calc(100%-16.5rem)`, so it never overlaps a button at 360–375 px. (History: one-finger orbit fought thumb scrolling; then turning was removed entirely, which he did NOT want: "I want to move around".) Portrait overview fits the rack to the screen width (no ceiling). Two-finger touches and Safari `gesture*` events on the canvas are preventDefault-ed so iOS Safari never pinch-zooms the page instead (user asked: thumb scrolling fought with orbiting, then dropped two-finger turning too). Hotspots zig-zag left/right down the rack on all screens, placed on plain panel, never over vendor logos/labels (`hotspot` in `devices.ts`). The hero name card slides away on phones once the visitor explores (`onExplore` signal → `rack-section.tsx`); a corner tab restores it.
- Git for Windows may rewrite files to CRLF (e.g. after `git stash`); normalize `\r\n` before string-replacing in scripts.
- Photo mode (three-gpu-pathtracer) was built and then removed (grainy/dark, GPU busy while scrolling) — in git history (`ec5325b`) if ever needed.
